typed causal edges (strauss_links) with kb_impact and kb_backlinks

Records may now carry `strauss_links` — `{ target, rel }` edges from a closed
vocabulary of eight: `depends_on`, `constrains`, `informs`, `blocks`,
`invalidates`, `verified_by`, `satisfies`, `related_to`. An edge lives on the
source record's frontmatter and reads source → target, so `A depends_on B`
means A needs B. Supersession is deliberately not a rel: it is a lifecycle, and
`strauss_supersedes`/`strauss_superseded_by` already carry it in both
directions. Each link is also rendered into the body as one prose sentence from
a fixed template per rel, so a consumer that knows only OKF still reads the
meaning off a markdown link with the kind in the surrounding words.

Two new tools read the inbound direction. **`kb_impact`** (CLI `impact`) is the
transitive inbound closure over the causal rels — every rel but `related_to` —
answering "what breaks if this record changes"; every row carries its standing,
a superseded or rejected record is reported but not walked through, and each
such stopping point is named under `stopped`. **`kb_backlinks`** (CLI
`backlinks`) is the flat one-hop counterpart over every rel.

**Behaviour change to `kb_validate`.** Findings now carry a `severity` of
`error` or `warning`, and only errors fail the command's exit code. Every check
that existed before is an `error`, so an unchanged base gets an unchanged exit
code, but the shape of each object in the array has one more key — a caller
comparing findings by deep equality will need to account for it. The two new
checks split across the line: a `rel` outside the closed vocabulary is an
`error` (nothing can traverse it and no later write fixes it), while a link to
a record not in the bundle is a `warning` (writing a record before the one it
points at is ordinary). The frontmatter schema stays tolerant of an unknown rel
on purpose — a schema strict enough to reject one would make the file fail to
parse, and `list()` skips a file it cannot parse, so the bundle would drop the
record instead of reporting it. `kb_write` is strict and refuses to write one.

Typed links also join the shared edge inventory as the directed `typed-link`
kind, so `kb_pack` reaches a record named only in frontmatter and `kb_trace`
follows a declared dependency. `TRACE_EDGES` gains `typed-link`; body links
remain excluded from traces.

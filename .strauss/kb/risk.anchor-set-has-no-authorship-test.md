## Risk

anchor-set is in the reviewer gate's WRITE_VERBS, so it is held to the actor rule, load-before-write and the preflight — but not to the ownership test ruleFor applies to status and answer. agent:security can set the anchors of a record generated by a human or by another agent.

## Why it matters

Deliberate, and matching anchor-resolve --rebaseline, which is the same class of write on the same field and has no ownership test either. It is recorded rather than fixed because the two would have to change together, and because dropBaselines already stops the destructive half: a reviewer cannot silently discard evidence, only move it.

## Mitigation

dropBaselines gates the loss of a stamped anchor; every set lands as one anchor-set log entry naming the actor and the reason.

## Verification

None. Whether a reviewer should move an author's pointers at all is a policy question for the roster, not something the command can settle.
